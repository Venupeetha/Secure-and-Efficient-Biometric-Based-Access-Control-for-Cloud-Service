Designing Secure and Efficient Biometric-Based Secure Access Mechanism for Cloud Services

 


A client registers with a fingerprint and gets a private key. The Authentication Server (Trustee) authenticates the client and generates a session key. The Owner uploads files to the Cloud (Remote Server). The Cloud Server gives access control after a fingerprint check, and the Client downloads a file with the secret key generated by the Trustee. A wrong fingerprint or a wrong secret key is recorded as an attacker.

Demo logins:
Owner: Raja / Raja  |  Client: Harish / Harish
Remote Server (Cloud): Server / Server  |  Authenticate Server (Trustee): AServer / AServer
Authority: authority / authority

To log in as a Client or an Owner you also need the fingerprint image you registered with. The demo accounts use the fingerprint images from the original project (in seed_data/biometric_images/) - for example Raja.jpg for the Owner Raja, and Harish.jpg for the Client Harish.
